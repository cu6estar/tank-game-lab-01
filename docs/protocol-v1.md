# Бінарний протокол гри, версія 1

Специфікація формату, який реалізує `shared/src/codec/binary.js`. Константи (коди, версія) —
`shared/src/protocol/constants.js`; ті самі повідомлення в JSON — `shared/src/codec/json.js`
(вмикається `?codec=json` на клієнті).

## Загальні правила

| Правило        | Значення                                                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Порядок байтів | **little-endian**, явно в кожному `setX/getX(offset, true)`                                                                                     |
| Транспорт      | бінарні кадри WebSocket (`binaryType = 'arraybuffer'`)                                                                                          |
| Заголовок      | `u8 version` (=1), `u8 type`                                                                                                                    |
| Типи           | `0x01` INPUT, `0x02` PING (клієнт→сервер); `0x81` SNAPSHOT, `0x82` PONG (сервер→клієнт)                                                         |
| Валідація      | довжина перевіряється ДО читання; зайві/відсутні байти, версія, невідомий тип, зайві біти `flags` → `CodecError` → сервер закриває сокет (4001) |

Керування (join, чат, roster, welcome) лишається JSON-текстом: це рідкі повідомлення, зручні для налагодження.
Бінарні кадри приймаються тільки після `join`.

## Квантування

| Величина      | Подання                          | Точність                                        |
| ------------- | -------------------------------- | ----------------------------------------------- |
| Позиція       | `f32`                            | ≈1e-4 px на 1280 px                             |
| Кут           | `i16 = round(wrap(a)/π · 32767)` | крок 9.6e-5 рад (0.0055°), похибка ≤ 4.8e-5 рад |
| Швидкість     | `i16 = round(v · 8)`             | 0.125 px/с (діапазон ±4096 px/с)                |
| Кулдаун       | `u8 = round(c · 200)`            | 5 мс (до 1.27 с)                                |
| Ефекти (щит…) | `u8 = round(залишок · 10)`       | 0.1 с (до 25.5 с)                               |
| HP            | `u8`                             | точно                                           |

## INPUT (клієнт → сервер), `0x01`

```
u8  version | u8 0x01 | u8 n (1..8)
n × { u32 seq | i8 throttle(−1..1) | i8 turn | i8 turretTurn | u8 flags (bit0 = fire) }   по 8 байт
```

Клієнт у кожному пакеті шле **3 останні** вводи (надлишковість: втрата одного пакета не губить ввід).
Сервер відкидає `seq`, не новіші за вже прийнятий, і тримає чергу ≤ 10.

## SNAPSHOT (сервер → клієнт), `0x81`

```
u8 version | u8 0x81 | u32 tick
u8  nPlayers × { u8 slot | u32 ack | u16 score }                                    7 Б
u16 nShips   × { u16 id | u8 slot | f32 x | f32 y | i16 vx | i16 vy | i16 angle
                 | i16 turret | u8 hp | u8 cooldown | u8 shield | u8 rapid | u8 homing }   24 Б
u16 nBullets × { u16 id | u8 owner | f32 x | f32 y | i16 vx | i16 vy | u8 flags(bit0 homing)
                 | u16 tag }                                                        18 Б
u16 nAsteroids × { u16 id | f32 x | f32 y | i16 angle | u8 radius | u8 flags(bit0 homing)
                   | u16 seed }                                                     16 Б
u16 nPickups × { u16 id | f32 x | f32 y | u8 type }                                 11 Б
u8  nEvents  × { u8 type | u8 a | u8 b | f32 x | f32 y }                            11 Б
```

- `slot` 255 (`NO_SLOT`) — ворожий корабель; `owner` 255 — ворожа куля.
- `ack` — останній **виконаний** `seq` гравця: за ним клієнт викидає підтверджені вводи.
- `tag` кулі = `seq & 0xffff` вводу, що вистрілив: за нею клієнт впізнає свою передбачену кулю.
- `events`: `type` 1 FIRED (`a` = слот), 2 HIT (`a` = вид, `b` = 1, якщо щит), 3 EXPLODED (`a` = вид, `b` = радіус), 4 PICKUP.
- Вибухи (частинки) у знімок не потрапляють — це косметика клієнта.
- Приклад: 8 кораблів без решти = 2+4+1+0+2+8·24+2+2+2+1 = **208 Б** (JSON — 1400 Б).

## PING / PONG

```
PING: u8 version | u8 0x02 | u32 clientMs                       6 Б
PONG: u8 version | u8 0x82 | u32 echo | u32 serverTick          10 Б
```

`echo` — те саме число, що клієнт надіслав: RTT = `now − echo`, годинники не синхронізуються.

## Версіонування

Зміна розкладки = новий `BINARY_VERSION`; декодер відмовляється від чужої версії явно
(тест «wrong version / type rejected»). Керуючий JSON-протокол має власну версію (`PROTOCOL_VERSION = 2`
у `join`/`welcome`).
